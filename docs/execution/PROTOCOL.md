# Protocolo de ejecución

1. Desde la raíz Git, ejecuta `python3 scripts/quality/check_requirements.py` con Python 3.11 o posterior. Para una tarea que escribirá en la raíz, añade `--preflight` en el mismo contexto de ejecución. El control comprueba primero los originales y después crea, lee y retira un temporal en la raíz. Si el control de requisitos falla, suspende la ejecución con capacidad de escritura y comunica el motivo. Solo el humano protege los originales o entrega una nueva versión.
2. En el arranque del proyecto y ante una nueva entrega lee los insumos en este orden: estándar, PRD, rol, inventario de data, contexto, stack, interfaz, tarea y formato. Usa los archivos Markdown existentes para contexto, stack e interfaz. Consulta el PDF pertinente cuando haga falta evidencia. Al reanudar una entrega conocida, verifica la huella y recupera fase, decisiones vigentes y fuentes aplicables.
3. Para resolver contradicciones aplica la precedencia de §5: seguridad y autorizaciones → AGENTS y este protocolo → [documento maestro](../MASTER_DOCUMENT.md) → estándar → PRD humano → ADR aprobados → resto de RCTF → datos. Registra conflictos y pausa solo el trabajo afectado.
4. Consulta [progreso](PROGRESS.md), selecciona en [AGENTS](../../AGENTS.md) el skill de la tarea y verifica alcance, criterios y autorizaciones. Para una nueva etapa registra su plan, responsables y pruebas. Una tarea local autorizada puede avanzar hasta el próximo gate aplicable.
5. Registra comando, contexto, fecha con zona, resultado y evidencia en la [bitácora](EXECUTION_LOG.md). Actualiza trazabilidad y progreso. Repite el control RCTF después de la tarea y antes del cierre, integración o promoción. Si cambió la fuente, conserva el diagnóstico y solicita intervención humana.
